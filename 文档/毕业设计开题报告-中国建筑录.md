## 一、选题背景与研究意义

中国古建筑承载着营造技术、审美观念、社会组织与地域文化，是传统文化传播和数字文化遗产保护的重要对象。榫卯、斗拱、梁架、夯土、石拱、瓦作等内容具有鲜明的工程逻辑和文化含义，但在普通受众尤其是年轻用户中，往往因概念抽象、图文说明密集、学习门槛较高而难以形成持续兴趣。

近年来，数字文化遗产传播逐渐从静态展示转向沉浸式、交互式和叙事化体验。UNESCO 的 Dive into Heritage 等项目体现了数字技术在遗产展示、互动叙事和公众教育中的价值。游戏作为一种天然具备反馈、目标、挑战和探索动机的媒介，能够把文化知识嵌入玩家行为，使“了解文化”不再只依赖阅读，而是通过操作、选择、失败、修复和奖励形成体验式理解。

本课题以 Unity 2D 游戏《中国建筑录》为毕业设计对象，尝试将中国古建筑结构智慧转化为可收集、可战斗、可提交和可解锁的游戏系统。玩家在限定时间内探索建筑空间，收集结构水晶并返回基地修复图鉴，从而逐步解锁建筑详情。该课题兼具软件工程实践、数字媒体设计和传统文化传播意义，适合用毕业设计方式系统展开。

## 二、国内外研究现状

在国外研究与实践中，严肃游戏、游戏化学习和数字文化遗产展示已经形成较成熟的研究方向。MDA 框架从 Mechanics、Dynamics、Aesthetics 三个层面分析游戏，强调规则机制、运行行为和玩家体验之间的关联，为本课题把建筑知识转化为玩法系统提供了方法参考。严肃游戏研究也指出，教育、文化遗产、健康、训练等领域可以借助游戏媒介提升参与感和理解深度。

国际数字遗产项目常采用 3D 扫描、虚拟漫游、交互叙事和多媒体导览等方式，让用户以更直观的方式接触文化遗产。其优势在于真实感、资料完整性和空间还原度，但部分项目仍偏重“观看”与“导览”，玩家主动决策、资源管理和玩法挑战相对不足。

国内方面，传统文化数字化传播、文博游戏、线上展陈和文化科普类应用快速发展。中国古建筑主题常见于纪录片、展览、交互网页、AR/VR 导览和文创游戏中，福建土楼、赵州桥等代表性建筑也具有较高公众认知度。现有成果在视觉呈现和知识普及方面较丰富，但仍存在知识与玩法割裂、互动目标单一、学习反馈不连续等问题。

因此，本课题的研究切入点不是单纯复原建筑外观，而是把古建筑结构知识拆解为游戏对象：结构水晶、背包词条、图鉴槽位、进度条和建筑详情。通过“探索—战斗—撤离—修复—阅读”的闭环，将文化内容从静态文本转化为玩家行动的一部分。

## 三、研究目标与主要内容

本课题目标是设计并实现一款基于 Unity 的 2D 像素风中国古建筑文化探索游戏。作品以《中国建筑录》为叙事入口，玩家作为书中世界的修复者，进入被灾害投影侵蚀的建筑空间，收集结构水晶、躲避或击败敌人、管理背包资源，并将材料提交到图鉴中修复福建土楼、赵州桥等建筑条目。

研究内容包括四个层面。第一，文化内容层：梳理代表性古建筑的结构特点，将榫卯、斗拱、梁架、石基、夯土、瓦片、敞肩拱等知识点转化为可识别的图标、道具和说明文本。第二，玩法系统层：设计轻 Rogue 与搜打撤结合的核心循环，让玩家在时间限制、敌人威胁、背包容量和提交收益之间作出选择。

第三，工程实现层：基于 Unity 2022.3.62f3c1、C#、Tilemap、Rigidbody2D、Collider2D、Animator、UGUI 和 TextMeshPro 实现主菜单、探索场景、角色移动、墨笔攻击、敌人状态、背包、图鉴、建筑详情、失败界面等模块。第四，展示交付层：整理项目文档、运行说明和 WebGL 发布链路，使成果能够用于毕业答辩和线上试玩。

| 研究内容 | 具体说明 |
| --- | --- |
| 文化知识建模 | 梳理中国古建筑代表案例，提取结构、材料、空间组织和防灾智慧等知识点，形成结构水晶、图鉴槽位和详情文本。 |
| 核心玩法设计 | 设计轻 Rogue 与搜打撤结合的行动循环，通过时间、背包容量、敌人压力和资源收益构成决策张力。 |
| Unity 系统实现 | 完成角色、敌人、交互、背包、图鉴、UI、倒计时、场景切换等模块，并通过组件化脚本降低耦合。 |
| 文化表达转化 | 将建筑知识嵌入道具属性、建筑进度、小图标点亮和详情页，使知识成为玩法反馈而非单独说明。 |
| 测试与优化 | 围绕操作流畅度、UI 可理解性、资源平衡、展示稳定性和 WebGL 兼容性进行测试和迭代。 |

## 四、拟解决的关键问题

1. 传统建筑知识如何转化为可玩的系统。古建筑知识如果只以文字说明出现，容易成为游玩之外的附加材料。本课题需要将结构知识拆解为资源、属性、图鉴槽位和解锁条件，使玩家在完成目标的过程中自然接触相关知识。

2. 搜打撤玩法节奏如何与文化学习目标协调。若战斗压力过强，会挤压文化阅读；若压力过弱，则游戏缺少挑战。本课题通过 300 秒倒计时、最后 60 秒高风险提示、6 格背包限制和基地暂停机制，形成适合短时试玩的节奏。

3. 多系统状态如何保持一致。背包、角色属性、建筑进度、图鉴槽位和 UI 显示之间存在数据联动。本课题采用 Model / Controller / View 分层思路，并通过管理器、事件通知和统一交互接口降低耦合。

4. 现场展示与用户理解如何保障。毕业答辩或比赛展示通常时间有限，因此界面提示、交互路径、失败恢复和文档说明必须清晰。项目需要保证从主菜单到探索、提交、点亮、详情页的演示路径稳定可复现。

## 五、技术路线与实现方案

项目采用“内容建模—机制映射—Unity 原型—系统开发—测试优化—展示交付”的技术路线。首先从中国古建筑案例中抽取结构关键词，将其设计为结构水晶、建筑宝藏、图鉴槽位和说明文本；随后把文化对象映射到玩家行为中，形成拾取、提交、点亮和详情解锁等机制。

工程上，Unity 的 GameObject 与 MonoBehaviour 负责场景对象和生命周期调度。角色移动使用 Rigidbody2D 和旧版 Input Manager 实现四方向控制；战斗模块通过 PlayerAttack、InkBall 和敌人受击判定形成墨笔攻击反馈；敌人模块通过巡逻、追击、攻击、返回出生点等状态形成探索压力；背包模块以固定 6 格容量承载资源取舍；图鉴模块通过建筑进度条、小图标槽位和详情页呈现文化内容。

UI 层使用 UGUI、TextMeshPro、Slider、Button 和 CanvasGroup 实现 HUD、背包、交互提示、图鉴主页、提交窗口、弹窗和失败界面。通过 UIRootManager 等统一控制图鉴和弹窗打开时的输入阻塞，避免玩家在阅读或提交时误触攻击。构建层面以 Windows PC 为主要运行平台，并保留 WebGL / GitHub Pages 在线试玩发布路线。

| 阶段 | 技术任务 |
| --- | --- |
| 内容分析 | 查阅中国古建筑和数字文化传播资料，确定建筑条目、结构关键词和知识解释口径。 |
| 机制映射 | 把结构知识映射为可拾取资源、临时属性、图鉴进度、结构槽位和建筑详情解锁条件。 |
| 原型搭建 | 使用 Tilemap、Sprite、Rigidbody2D、Collider2D、Animator 搭建可移动、可攻击、可拾取的 2D 原型。 |
| 系统开发 | 通过 IInteractable、管理器、事件通知和 CanvasGroup 统一处理交互、背包、图鉴、UI 阻塞和状态刷新。 |
| 体验打磨 | 调整倒计时、敌人行为、背包容量、按钮反馈和说明弹窗，确保“搜、打、撤、修复、阅读”的闭环清晰。 |
| 构建交付 | 输出 Windows 可运行版本，整理运行文档，并基于 GitHub Actions / WebGL 链路准备线上试玩版本。 |

## 六、研究方法

文献与案例分析法：查阅中国建筑史、数字文化遗产、严肃游戏、MDA 游戏设计框架和 Unity 官方文档，明确课题理论基础与技术依据。

需求分析法：从毕业设计展示、玩家试玩和文化传播三个角度分析功能需求，确定主流程、核心交互、界面层级和文档交付范围。

原型迭代法：先实现移动、拾取、战斗和图鉴的最小可玩闭环，再逐步补充敌人、倒计时、背包限制、UI 反馈和建筑详情内容。

模块化设计法：将项目划分为角色控制、敌人 AI、背包资源、图鉴修复、UI 管理、场景切换和文档交付等模块，降低系统维护难度。

测试反馈法：通过编辑器 Play Mode、Windows 构建试玩和演示路径检查，对操作响应、资源提交、图鉴解锁、失败恢复和界面遮挡等问题进行验证。

## 七、可行性分析

技术可行性方面，Unity 2022.3 LTS 对 2D 游戏开发、Tilemap、物理碰撞、动画、UGUI 和 WebGL 构建均提供成熟支持；项目已有完整的 Packages、ProjectSettings、场景资源和脚本基础，能够支撑毕业设计实现。

内容可行性方面，福建土楼、赵州桥等建筑具有清晰的结构特征与文化价值，便于提取为游戏化对象。项目不追求大型 3D 写实复原，而采用 2D 像素风与图鉴解释，开发量更适合毕业设计周期。

资源可行性方面，工程中已经包含角色、敌人、建筑图鉴、道具图标、Tilemap、UI 素材和文档资料。现有操作手册、设计文档和运行说明可直接转化为论文与答辩材料。

风险控制方面，若后期时间不足，可优先保证核心闭环完整：移动、拾取、战斗、背包、提交、点亮、详情页和失败恢复。建筑条目数量、问答系统、拍照系统和更多 WebGL 适配可作为扩展目标。

## 八、创新点与特色

1. 将古建筑结构知识数据化。项目不是把建筑作为背景贴图，而是把榫卯、斗拱、梁架、夯土、瓦片、石拱等结构概念转化为玩家可收集、可提交、可点亮的对象。

2. 以搜打撤循环承载文化传播。玩家需要在时间、敌人、背包和收益之间做决策，文化知识通过行动结果进入图鉴和详情页，降低了单纯阅读带来的距离感。

3. 图鉴修复机制形成长期目标。建筑进度条与小图标槽位共同决定建筑解锁，既有数值进度反馈，也有结构知识点的逐步揭示。

4. 工程结构清晰，便于扩展。Model / Controller / View 分层、统一交互接口、管理器与事件机制使后续扩充建筑条目、敌人类型、关卡主题和问答内容具有可操作性。

## 九、预期难点与解决措施

文化准确性难点：建筑结构知识需要避免误读和泛化。解决措施是以权威建筑史资料、UNESCO 世界遗产资料和官方文化报道为参考，对游戏内说明文本进行人工校对。

玩法平衡难点：时间限制、敌人伤害、墨水消耗、背包容量和建筑进度之间需要平衡。解决措施是先保证演示闭环，再通过试玩调整数值，使玩家能在短时间内体验完整流程。

UI 状态难点：图鉴、详情页、提交窗口、弹窗和战斗输入容易冲突。解决措施是使用 CanvasGroup 和统一 UI 管理器控制输入阻塞，并在关键交互处提供明确提示。

构建兼容难点：Windows 与 WebGL 环境存在加载、输入和资源路径差异。解决措施是以 PC 端稳定运行为主，同时保持 WebGL 构建流程和 CI/CD 文档，逐步验证线上试玩。
